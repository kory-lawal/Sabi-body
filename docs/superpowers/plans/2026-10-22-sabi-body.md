# Sabi Body Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build Sabi Body, a browser-based multilingual-ready fitness coach that locally tracks squats, jumping jacks, and planks with MediaPipe Pose Landmarker.

**Architecture:** Use a small Vite app with vanilla JavaScript ES modules. Keep exercise analysis pure and independently tested, camera/MediaPipe lifecycle isolated from UI, and feedback message lookup/speech separate from the app controller.

**Tech Stack:** HTML5, CSS3, JavaScript ES modules, Vite, `@mediapipe/tasks-vision`, Canvas API, Web Speech API, and Node's built-in `node:test`.

**Spec:** `docs/superpowers/specs/2026-10-22-sabi-body-design.md`

## Global Constraints

- The first version supports squats, jumping jacks, and planks, using a camera and MediaPipe Pose Landmarker to derive movement feedback and progress.
- Camera frames stay in the browser and are not recorded, uploaded, or stored.
- A Vite application using HTML, CSS, and vanilla JavaScript ES modules.
- Use the official `@mediapipe/tasks-vision` package.
- Do not request camera access on page load.
- On Start, request a user-facing video stream and initialize one `PoseLandmarker` in `VIDEO` mode with `numPoses: 1`.
- Run `detectForVideo()` from one `requestAnimationFrame` loop.
- English is the complete initial dictionary. The other supported languages have no invented entries.
- Speak only English messages when English is selected, when the browser supports speech synthesis, and when the cooldown allows it.
- Browser code must never contain API keys.
- No accounts, databases, video upload/recording, server/API, medical advice, or remote YarnGPT speech generation.
- Run the production Vite build after implementation.

## Task 2: Implement and Test Landmark Geometry and Squats

**Files:**
- Create: `src/exercises/geometry.js`
- Create: `src/exercises/squat.js`
- Create: `test/exercises.test.js`

**Interfaces:**
- `angleAt(a, b, c)` accepts `{x, y}` points and returns an angle in degrees at `b`; return `null` for missing, degenerate, or non-finite points.
- `isVisible(landmark, threshold = 0.55)` returns `true` only when `x` and `y` are finite and the landmark's visibility/presence evidence meets the threshold. Treat a missing visibility/presence field as unreliable.
- `hasFullBodyVisible(landmarks)` returns `true` only when nose, both shoulders, both hips, both knees, and both ankles pass `isVisible`.
- `createSquatAnalyzer()` returns `{ update(landmarks), reset() }`. `update` returns `{ count, state, feedbackId }`; if required landmarks are unreliable, keep count/state and return `feedbackId: "body-not-visible"`.
- Pose landmark indices follow MediaPipe Pose Landmarker: left hip/knee/ankle `23/25/27`, right `24/26/28`.

- [ ] **Step 1: Write failing geometry and squat tests**

Create `test/exercises.test.js` using `node:test` and `node:assert/strict`. Add tests that:

1. `angleAt({x: 1, y: 0}, {x: 0, y: 0}, {x: 0, y: 1})` is approximately `90`.
2. `angleAt` returns `null` for coincident points and missing inputs.
3. `isVisible` rejects missing visibility, a visibility below `0.55`, and non-finite coordinates.
4. `hasFullBodyVisible` is false if any required full-body landmark is absent or unreliable and true when all required landmarks are reliable.
5. A sequence with knee angles `[170, 145, 105, 140, 170]` produces exactly one squat count.
6. An incomplete sequence `[170, 145, 170]` does not count.
7. Repeated low-angle frames do not count repeatedly.
8. An unreliable frame in the middle of a squat neither advances the state nor increments the count.
9. `reset()` clears the count and restores the initial phase.

Use a helper that creates pose arrays of 33 landmarks with the chosen left-side hip/knee/ankle points and visibility `0.9`; encode the desired knee angle with simple fixed-length points.

- [ ] **Step 2: Run the focused tests and confirm they fail**

Run:

```powershell
node --test test/exercises.test.js
```

Expected: failures report missing exports or missing module files.

- [ ] **Step 3: Implement reusable geometry**

Implement `angleAt` with vector dot product, clamped cosine, and `Math.acos`. Implement `isVisible` using finite normalized coordinates and the strongest available `visibility`/`presence` score, requiring at least one score. Implement `hasFullBodyVisible` with landmark indices nose `0`, shoulders `11/12`, hips `23/24`, knees `25/26`, and ankles `27/28`.

- [ ] **Step 4: Implement the squat state machine**

Use centralized thresholds of `160` degrees for standing and `110` degrees for squat depth. A reliable standing frame arms the state machine. A decrease below the standing threshold enters lowering; reaching squat depth records a valid bottom; recovery above the bottom threshold enters returning; only a subsequent standing threshold increments count and returns to standing. Choose the reliable side with the greatest minimum visibility across hip/knee/ankle; average both knee angles when both sides are reliable. Return stable phase names and IDs `return-to-start`, `move-lower`, `great-job`, and `keep-going` based on phase transitions. Unreliable input must not advance phases.

```powershell

```

## Task 3: Implement and Test Jumping Jacks and Plank

**Files:**
- Create: `src/exercises/jumping-jacks.js`

**Interfaces:**
- `createJumpingJackAnalyzer()` returns `{ update(landmarks), reset() }`; `update` returns `{ count, state, feedbackId }`.
- `createPlankAnalyzer()` returns `{ update(landmarks, nowMs), reset() }`; `update` returns `{ elapsedMs, active, state, feedbackId }`.
- Reuse `isVisible` and `angleAt` from `geometry.js`.

- [ ] **Step 1: Add failing jumping-jack tests**

Add tests for the 33-landmark pose fixture that verify:

1. A closed → open → closed sequence counts exactly one jack.
2. Open frames alone and a partial closed → open sequence count zero.
3. Repeated closed frames after a completed cycle do not add counts.
4. Missing/unreliable wrist or ankle landmarks do not advance state.

Use landmark indices: shoulders `11/12`, wrists `15/16`, hips `23/24`, ankles `27/28`. Define closed as wrists below the shoulders (larger `y`) and ankle width no more than `1.15 ×` hip width. Define open as both wrists above shoulders and ankle width at least `1.35 ×` hip width.

- [ ] **Step 2: Add failing plank tests**

Add tests that verify:

1. A reliable side-on shoulder/hip/ankle sequence with hip angle within `20` degrees of straight accrues elapsed milliseconds.
2. A bent alignment does not accrue time and emits `adjust-alignment`.
3. Unreliable landmarks pause accrual and the following valid frame starts a new interval instead of counting the gap.
4. `reset()` clears accumulated time.
5. A single time delta is capped at `200 ms` to avoid background-tab pauses inflating the timer.

Use left-side indices `11/23/27` when visible, otherwise right-side `12/24/28`; require all three points from one side.

- [ ] **Step 4: Implement jumping-jack analysis**

Require reliable shoulders, wrists, hips, and ankles on both sides. Compute ankle width and hip width in normalized image coordinates. Start in `waiting-for-closed`; transition to `closed` when the closed thresholds are met, `open` only after a complete open pose, then count once upon returning to closed. Repeated frames in a state do not increment.

- [ ] **Step 5: Implement plank analysis**

Compute the shoulder–hip–ankle angle for the reliable side and classify it as aligned when `abs(angle - 180) <= 20`. Accumulate only the gap between successive valid aligned frames, capped at `200 ms`; clear the previous timestamp on every unreliable or misaligned frame. Return `aligned`, `adjust-alignment`, or `body-not-visible` message IDs as appropriate.

## Task 5: Implement Deferred Camera and MediaPipe Tracking

**Files:**
- Create: `src/camera/camera.js`
- Create: `src/pose/draw-pose.js`
- Create: `src/pose/pose-tracker.js`
- Modify: `package.json` only if needed for the official package import.

**Interfaces:**
- `startCamera(videoElement)` requests `{ video: { facingMode: "user" }, audio: false }`, assigns the stream, awaits playback, and returns the `MediaStream`.
- `stopCamera(stream, videoElement)` stops every track and clears `srcObject`.
- `drawPose(canvas, landmarks, videoElement)` draws visible landmarks/connections using coordinates aligned with the rendered video.
- `createPoseTracker({ onPose, onError })` returns `{ start(videoElement, canvas), pause(), resume(), stop() }`. It creates one `PoseLandmarker` in VIDEO mode with `numPoses: 1`, runs only one animation-frame loop, and closes the landmarker on stop.

- [ ] **Step 1: Implement camera stream lifecycle**

Implement deferred `getUserMedia` in `startCamera`; do not call it at module load or from Home rendering. On stream assignment/playback failure, stop all acquired tracks, clear the video source, and throw a descriptive error. Implement idempotent `stopCamera`.

- [ ] **Step 2: Add the overlay renderer**

Use `PoseLandmarker.POSE_CONNECTIONS`. Match the canvas backing dimensions to the video dimensions and apply the same mirroring transform as the displayed preview. Draw only connections and points whose endpoint landmarks are visible. Resize for device pixel ratio without changing normalized pose coordinates.

- [ ] **Step 3: Implement MediaPipe initialization**

Import `FilesetResolver` and `PoseLandmarker` from `@mediapipe/tasks-vision`. Resolve the package's WASM files and create `PoseLandmarker` in VIDEO mode with one pose. Use the official pose landmarker model asset. Keep model initialization inside `start`, so importing the application does not request camera or load the model.

- [ ] **Step 4: Implement the single-frame loop**

Store one RAF handle and one `lastVideoTime`. Each scheduled callback checks running state, waits for a ready video frame, calls `detectForVideo(videoElement, performance.now())` only when `video.currentTime` has advanced, draws landmarks, and calls `onPose(landmarks, timestamp)`. Schedule at most one next callback. `pause()` cancels the current handle and prevents inference; `resume()` starts one loop if stopped/paused; `stop()` cancels the loop and closes the landmarker.

- [ ] **Step 5: Handle cleanup and failure paths**

If model setup or inference fails, cancel the loop, close any initialized landmarker, invoke `onError` with a descriptive `Error`, and reject `start` on initialization failure. Camera cleanup remains the app controller's responsibility. Handle track `ended` in the controller by pausing tracking and reporting camera interruption.

Run:

```powershell

```

Expected: Vite bundles the official package without import errors. Hardware camera/model behavior remains subject to the manual verification in Task 7.
